# 까만 막대

사진 속 **얼굴·사람·화면(원하면 차량까지)을 까만 막대로 가리고**, 사진에 숨은 **위치정보(EXIF)를 지우는** 웹 앱입니다.

- **사진이 기기 밖으로 나가지 않습니다.** 모델이 브라우저 안에서 돌아갑니다(ONNX Runtime Web, WebAssembly). 서버로 보내는 요청은 앱 파일과 모델을 받을 때뿐입니다.
- **가입이 필요 없습니다.**
- **여러 장 한꺼번에:** 최대 50장을 골라 차례로 처리하고, 한 장씩 넘겨 확인한 뒤 zip 하나로 저장하거나 한꺼번에 공유합니다.
- **PWA:** 홈 화면에 추가할 수 있고, 한 번 연 뒤에는 인터넷 없이도 동작합니다.

## 왜 블러가 아니라 까만 막대인가

블러나 모자이크는 원래 픽셀을 섞어 둔 것이라 AI로 일부 되살릴 수 있습니다. 까만 막대는 그 자리의 픽셀을 덮어써서 원래 정보가 남지 않습니다.

## 동작

1. 사진을 고르면 원본 크기로 다시 그립니다(EXIF 방향 반영, 최대 4096px).
2. 640×640으로 줄인 같은 그림을 두 모델에 넣습니다.
   - YOLO26n: 사람(COCO `person`), 화면(`tv`, `laptop`, `cell phone`), 차량(`car`, `motorcycle`, `bus`, `truck`)
   - YuNet: 얼굴 (OpenCV Zoo, 약 230KB)
3. 사람 가리기는 두 가지입니다.
   - **얼굴(기본):** 사람 상자 위쪽에 얼굴이 있으면 얼굴만 가립니다(머리카락·귀까지 넓혀서). 얼굴을 못 찾은 사람(뒷모습, 작게 찍힘)은 예전처럼 상자 위쪽을 어림해서 가립니다. 사람 상자 밖에서 찾은 얼굴도 가립니다.
   - **몸 전체:** 사람 상자 전체. 그 밖에서 찾은 얼굴은 따로 가립니다.
4. 화면·차량은 상자 전체를 가립니다. 번호판만 따로 찾지는 못합니다.
5. 막대를 누르면 켜고 끄고, 빈 곳을 끌면 막대를 새로 그립니다. 여러 장이면 위의 작은 사진이나 ←/→ 키로 넘깁니다. 본 사진에는 ✓가 붙습니다.
6. 저장하면 새 캔버스에서 JPEG로 만듭니다. 그래서 EXIF(위치·기기·시간)가 들어가지 않습니다. 여러 장은 압축 없이 묶은 zip 하나로 받습니다.

## 기본값을 정한 이유

| 값 | 기본 | 이유 |
|---|---|---|
| 민감도(점수 임계값) | 0.20 | 개인정보는 **놓치는 쪽이 더 큰 손해**라 낮게 둡니다. 잘못 가린 막대는 눌러서 끄면 됩니다 |
| 사람 범위 | 얼굴 | 얼굴을 가리면서 사진은 남깁니다. 얼굴을 못 찾으면 머리 쪽 어림값으로 되돌아가서, 사람을 찾은 이상 막대가 빠지지는 않습니다 |
| 얼굴 점수 기준 | 0.6 | 사람이 없는 사진 100장에서 잘못 그린 얼굴 막대: 0.5 → 11개, **0.6 → 7개**, 0.7 → 3개. 놓치는 쪽이 더 손해라 0.7보다 한 단계 낮춤. 0.6과 0.7에서 얼굴을 놓치는 차이는 재지 않음(얼굴 정답 없음) |
| 차량 | 끔 | 차는 대개 사진에서 크게 찍혀 켜 두면 사진 대부분이 까매집니다(`bus.jpg`). 번호판이 문제일 때만 켭니다 |
| 한 번에 다룰 사진 | 50장 | 원본은 파일 그대로 들고 있고, 보고 있는 사진 한 장만 큰 캔버스로 풀어 둡니다. 휴대폰 메모리 기준 |
| 사람 판정 | 다른 클래스 점수가 더 높아도 사람 후보면 유지 | 같은 이유(놓치지 않기). 화면 클래스는 가장 높은 점수일 때만 씁니다 |

## 확인한 것

| 확인 | 결과 |
|---|---|
| ONNX와 PyTorch 결과 비교 (`bus.jpg`) | 같은 사람 4명과 버스를 찾음. 왼쪽 가장자리 사람 점수는 0.654 → 0.53으로 낮아짐(입력을 640×640 정사각형으로 채우는 방식 차이). 기본 민감도 0.20에서는 그대로 가려짐 |
| 브라우저 추론 시간 | 약 0.2초 (데스크톱, 단일 스레드 WASM) |
| EXIF 삭제 | GPS·카메라 정보·회전 값을 넣은 시험 사진 → 저장본에 `Exif`·카메라 이름 없음. 회전 값은 반영되어 똑바로 저장 |
| 오프라인 | 로컬 서버를 끈 상태에서 새로고침 → 모델 로드와 추론 정상 |
| 휴대폰 폭 (375px) | 가로 스크롤 없음, 공유 버튼 표시. 여러 장일 때 이전·다음, 작은 사진 줄도 가로 스크롤 없음 |
| 얼굴 모델 풀이 | 내가 짠 출력 풀이(`tools/check_yunet.py`, app.js와 같은 계산)와 OpenCV `FaceDetectorYN`이 `bus.jpg`에서 같은 얼굴 2개, 같은 점수(0.900, 0.893)·좌표. 브라우저에서도 0.900, 0.892 |
| 여러 장 | 예시 2장을 연달아 넣음 → 차례로 처리(각 약 0.24초), 넘기면 그 사진의 막대가 나옴 |
| zip | app.js의 zip 코드로 만든 파일을 Python `zipfile`과 `unzip -t`로 검사 → CRC 오류 없음, 한글 파일 이름 유지 |

## 측정: 사람을 얼마나 놓치나

`tools/eval_recall.py` 로 COCO val2017(모델 학습에 쓰지 않은 사진)에서 쟀습니다. 사람이 있는 사진 400장(사람 1,542명)과 사람이 없는 사진 100장입니다. 정답 박스와 IoU 0.5 이상 겹치면 찾은 것으로 셉니다. 브라우저와 같은 ONNX 파일·같은 규칙을 파이썬으로 돌렸고, 사진 줄이는 방식만 다릅니다. 결과 전체는 `eval/result.json`에 있습니다.

| 민감도 | 찾은 사람 | 얼굴로 더 잡은 것까지 | 크게 찍힘 | 중간 | 작게 찍힘 | 정답 없는 사람 막대(장당) |
|---|---|---|---|---|---|---|
| 0.10 | 76.0% | 77.9% | 95.0% | 84.8% | 44.9% | 2.21 |
| 0.15 | 72.1% | 74.6% | 94.4% | 79.5% | 38.8% | 1.38 |
| **0.20 (기본)** | **69.0%** | **72.2%** | **93.3%** | **75.7%** | **34.2%** | **0.94** |
| 0.30 | 62.6% | 67.6% | 91.5% | 66.5% | 25.6% | 0.45 |
| 0.50 | 50.1% | 58.9% | 85.5% | 49.4% | 10.7% | 0.14 |

크기는 COCO 기준(원본에서 32×32px 미만이면 작게, 96×96px 이상이면 크게)입니다. 사람 수는 작게 477, 중간 526, 크게 539명입니다.

**읽는 법**
- 크게 찍힌 사람은 기본값에서 **15명 중 1명**을 놓칩니다. 작게 찍힌 사람은 **3명 중 2명**을 놓칩니다. 기본값에서 놓친 사람(얼굴로도 못 잡은 것) 중 처음 400명을 보면 작게 293, 중간 85, 크게 22명입니다.
- 얼굴 모델을 더하면 2~9%p 더 잡습니다. 민감도가 높을수록(사람 상자가 적을수록) 효과가 큽니다.
- 민감도를 0.10으로 내리면 7%p 더 찾지만 잘못 그린 막대가 장당 1개에서 2개로 늡니다. 기본값 0.20은 그대로 두고, 사람이 많은 사진에서는 슬라이더를 내리라고 화면에 적었습니다.
- '몸 전체'로 가렸을 때 정답 사람 상자의 절반 이상이 덮인 비율은 80.5%입니다(0.20).
- 차량(자동차·오토바이·버스·트럭 382대) 중 찾은 비율은 65.4%입니다(0.20).

**이 숫자의 한계**
- COCO 사진은 거리·운동장처럼 멀리 있는 사람이 많은 편입니다. 셀카·단체 사진에서는 더 높게 나올 수 있습니다. 내 사진으로 잰 값이 아닙니다.
- 얼굴을 정확히 가렸는지는 재지 않았습니다. 얼굴 정답 박스가 없어서, '사람 상자 위쪽 절반에 얼굴이 있으면 가려진 것'으로 셌습니다.
- 정답 없는 사람 막대에는 COCO가 '무리(crowd)'로 따로 표시한 사람들도 섞여 있어, 실제 잘못 가림보다 많게 셉니다.

다시 재려면:

```bash
python tools/eval_recall.py <val2017 사진 폴더> <labels/val2017 폴더> <사진 목록.txt>
```

사진은 `http://images.cocodataset.org/val2017/<번호>.jpg`, 라벨은 Ultralytics `coco2017labels.zip`에서 받았습니다. 사진 목록은 `eval/result.json`의 `images`에 있습니다. 사진·라벨은 저장소에 넣지 않았습니다(COCO 사진은 Flickr 사진마다 라이선스가 다름).

## 못 하는 것 (꼭 직접 확인)

- **작게 찍힌 사람은 대부분 놓칩니다**(위 측정에서 3명 중 2명). 큰 사진도 640px로 줄여서 보기 때문입니다. 사진을 잘라 여러 번 보는 방식(타일링)은 아직 넣지 않았습니다.
- **얼굴을 못 찾은 사람**은 사람 상자에서 계산한 머리 쪽 어림값으로 가립니다. 누워 있거나 잘린 사람은 빗나갈 수 있습니다.
- **번호판, 택배 송장, 이름표, 화면 속 글자**는 찾지 못합니다. COCO 80종에 없기 때문입니다. 차량은 차 전체를 가리는 것만 됩니다.
- HEIC 사진은 브라우저가 열 수 있을 때만 됩니다(Safari는 가능, 일부 Chrome은 불가).

## 실행

정적 파일뿐이라 아무 정적 서버로 열면 됩니다. 서비스 워커 때문에 `file://`가 아니라 `http://localhost`로 열어야 합니다.

```bash
python3 -m http.server 8765
```

브라우저에서 `http://localhost:8765`를 엽니다.

## 파일

| 경로 | 내용 |
|---|---|
| `index.html`, `app.js` | 화면과 동작 (빌드 없음) |
| `sw.js`, `manifest.webmanifest`, `icons/` | PWA (오프라인 캐시, 홈 화면 추가) |
| `model/yolo26n.onnx` | `yolo export model=yolo26n.pt format=onnx imgsz=640` (ultralytics 8.4.208) |
| `model/face_detection_yunet_2023mar.onnx` | OpenCV Zoo YuNet 얼굴 모델 (MIT, `model/LICENSE-yunet.txt`) |
| `tools/eval_recall.py` | 놓치는 비율 측정 |
| `tools/check_yunet.py` | 얼굴 모델 출력 풀이를 OpenCV와 대조 |
| `eval/result.json` | 측정 결과 (민감도별 표, 놓친 사람 목록) |
| `vendor/ort/` | onnxruntime-web 1.20.1 (MIT). CDN 대신 직접 포함해서 외부 요청이 없음 |
| `samples/` | `bus.jpg` (Ultralytics 예제, AGPL-3.0), `laptop-desk.jpg` (Wikimedia Commons, CC0) |

## 라이선스

YOLO26 모델은 Ultralytics의 AGPL-3.0입니다. 얼굴 모델 YuNet은 MIT입니다. 그래서 이 앱도 AGPL-3.0으로 공개합니다(`LICENSE`). 유료 서비스로 바꾸려면 소스를 계속 공개하거나 Ultralytics 기업 라이선스가 필요합니다.
